# Agent実行規約

既存のCursorプロジェクトと同じ実行制約を維持します。GPT-6 Astraが主担当の場合、子Agent・CLI worker・名称を変えた子processによる委譲は禁止です。モデルを確定できない場合も別モデルだと推測して許可しません。通常のファイル・Git・テスト・API操作で進めます。

他モデルでも、現在のクライアントと本人の依頼範囲に従います。独立レビューはwriterとは別の許可されたセッションで行い、同じセッションの自己レビューを代用しません。別チャット作成や既存チャットへの依頼は、当該操作について本人が許可した経路を使います。既存チーム内の依頼済み作業は根拠・範囲・対策を引き継ぎ、毎回本人へ確認しません。利用可能な経路がなければreview packetを完成させ、実際に不足する権限・本人操作と、独立して継続できる作業を分けます。[継続判断](workflow.md#公開操作の承認範囲と失敗の扱い)は、クライアントが要求する明示依頼や上記の委譲禁止を解除しません。

coordinatorの`tick`はCLI workerを起動し得ます。独立top-level sessionと自動的に同一視せず、子Agent禁止を迂回するために使いません。read-onlyの`scan`と回帰試験はworker起動と区別します。

チームの役割・必要時の編成・解体と人間向け窓口は[連絡規約](team-communication.md)に従います。窓口専任chatや新しい作業chatも実際の本人依頼とtool条件が前提です。窓口は常時稼働・実装・監視を担わず、上記の子Agent禁止を別chat/workerという名称で迂回しません。
