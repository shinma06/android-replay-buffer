# GUIの情報設計（Trail #21）

ToolWindowと設定画面を、利用場面と頻度を根拠に組み直す。見た目の好みではなく、「いつ・何のために見るか」から表示の強弱と置き場所を決める。表示する情報そのものは減らさず、見る必要がある場面まで畳む。

## 利用場面と頻度

| 場面 | 頻度 | 利用者が知りたいこと・したいこと |
|---|---|---|
| ① 普段の開発中 | 常時（ほぼ見ない） | 取得が正常に回っているかを一目で確かめる |
| ② 不具合が起きた瞬間 | ときどき・最重要 | 迷わず1回押して、直前N秒またはスクショを残す |
| ③ 保存の直後 | 保存ごと | 保存できたか、どこに保存されたかを確かめ、開く |
| ④ 異常が起きたとき | まれ | 何が起きたか、次に何をすればよいか |
| ⑤ 準備 | 最初の1回・まれ | 保存先・対象アプリ・記録内容を決める |
| ⑥ 診断 | ほぼない | 区間・不足区間・SDKパス・セッションIDなどの内部状態 |

## 原則と根拠

| 原則 | 根拠 | この画面での適用 |
|---|---|---|
| 頻度の高い操作ほど上に大きく | Fittsの法則、操作頻度による配置 | ②の「直前N秒を保存」を最上部の主ボタンにする |
| 正常時は1行、異常時だけ展開 | 例外による管理（management by exception）、注意資源の節約 | ①は状態の見出し1行。取得の一部失敗・保存失敗・未解決などのときだけ、理由と次の操作を出す |
| 段階的な開示 | Progressive disclosure（Nielsen Norman Group） | ⑥の情報は「詳細」に畳む。消さない |
| 状態は記号・色・文字で重ねて示す | WCAG 1.4.1（色だけに頼らない） | 見出しの状態は、アイコン・色・文字を併記する |
| 記憶より再認 | Nielsenのヒューリスティクス（Recognition rather than recall） | ボタン名に結果を書く（「直前30秒を保存」）。無効のときは、その理由をボタンの近くに1行で出す |
| 同じ情報を2か所に出さない | 重複は比較と判断の負荷を増やす | 保存完了の詳細は通知に任せ、パネルは直近の結果1行と「フォルダを開く」だけにする |
| 説明は必要なときにだけ出す | 恒常的な説明文はバナー盲目を起こす | 「取得OFFで変更してください」などの制約は、違反しうる状態（取得ON中）にだけ表示する。常に有効な補足はツールチップに移す |

## ToolWindow

上から次の順に置く。

1. **状態の見出し:** `● 取得中 · <端末名> · <package>` を1行で表示し、右端に取得のON/OFFスイッチを置く。状態に応じてアイコンと色を変える（取得中・接続待ち・復旧中・一部失敗・無効）
2. **主な操作:** 「直前N秒を保存」（主ボタン）、「スクリーンショット」、「Logcatを開く／閉じる」。無効なボタンだけ、その理由を下に1行で出す
3. **直近の結果:** 保存やスクショをした後だけ表示する。成功は `保存しました <時刻> · フォルダを開く` の1行。失敗は目立つ枠で理由・再試行・別の保存先で再試行・破棄を出す
4. **注意:** 異常があるときだけ表示する。取得エラー、アプリ未解決（「設定を開く」へ誘導）、複数端末、反映待ち、片付け待ちなど
   - **取得する端末:** 2台以上が関係するとき（未選択で複数接続、選んだ端末の切断中にほかの端末が接続、IDE再起動後に選んだserialが未接続など）だけ、注意の下に選択欄を出す。先頭は取得中の端末（または `選んでください` / `<serial>（切断中）`）、serialを選んでいるときは末尾に `自動で選ぶ`。CLI `settings set device=`・MCP `update_settings` の `device` と同じ設定で、意味も同じ
5. **詳細（初期は畳む）:** 各記録（動画・端末ログ・アプリログ）の状態と秒数、保持時間と記録区間、不足・未確認区間、保存先、クラッシュ自動保存の状態、Android SDK、記録セッション、固定した保存対象
6. **設定への導線:** 末尾に「設定…」のリンク

## 設定画面

変更する頻度と場面で分ける。

1. **基本（最初の1回）:** 保存先、保持時間、対象アプリ（自動／手動とpackage名、解決結果）
2. **記録する内容:** 取得モード、動画品質、タップ位置の表示。取得ON中は操作を無効にし、「取得をOFFにすると変更できます」を1行だけ出す
3. **スクリーンショットの保存先:** Logcatに合わせる／手動
4. **クラッシュ時の自動保存:** スイッチ1つと、対応範囲の短い1行。上限や再開方法はツールチップに移す
5. **ターミナル・エージェント（初期は畳む）:** CLIの場所とコピー

検証の結果（保存先の誤りなど）は、その項目の直下にだけ出す。正常なときは何も出さない。

## 実装

ToolWindowと設定画面は、Android Studio同梱のCompose（Jewel、`intellij.platform.compose`）で作る。IDEのテーマに合わせて描画し、取得・保存の処理と状態の持ち方は変えない。画面に出す文言は、既存の説明関数（`captureDescription` など）を使い、意味を変えない。
