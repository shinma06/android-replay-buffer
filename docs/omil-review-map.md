# OMILの振り返りで使う34観点

原設計PLAN-OMIL-v0.2とW1のIDを保持した公開索引です。[フェーズ点検](omil-phase-review.md)で全領域を概観し、重要な変化・未知・相互作用を選ぶために使います。毎回34件の新試験や様式記入を要求するチェックリストではありません。現行の採用条件・旧判断との関係は[OMILの現行判断](omil-current.md)、公開と参照確認は[#278](https://github.com/shinma06/android-replay-buffer/issues/278)へ戻ります。

## 見る範囲

L1は価値/目的（R11/R12）、L2は権限/制約（R21/R22）、L3は機能/役割（R31/R32）、L4は全体の流れ（R41/R42）、L5は作業単位/依存（R51/R52）、L6は方法/品質（R61/R62）、L7は個別操作/版（R71/R72）です。Xは横断する情報・基盤・負担、Jは領域のつながり、AGはagent役割の作成・終了・継承を見ます。

下表の右欄は、2026-10-16の運営能力実証の最終評価を公開用に要約した**歴史上の限定評価**です。全34観点の普遍的PASS、現在の製品受入、新しいフェーズの合格ではありません。旧W1の「証拠不足」、旧C不支持、未実行は当時の状態として保持し、後続の限定証拠がどこに加わったかを区別します。「確認範囲内」「保持」は改善効果を証明したという意味ではありません。

## 評価の読み方と次の利用

A/Bは限定pilotと未提示条件へのadaptation v2、Cは固定ローカル検査の重複除去です。E0は初期の限定smokeと新PM/独立役の生成・受領・終了・再取得、S1/S2は品質を受領してもC改善を支持できなかった旧比較です。R1/R2等の失敗と後続Cの条件は[結果と旧判断の対応](omil-current.md#旧判断撤回をどう読むか)を参照します。名称を知っていることや表の判定だけで原証拠を再審査済みにしません。

原本はOMIL保管、当時の独立評価・採用受領はPMが担当しました。最終34観点評価は元要求 `OMIL-REMAINING-SPEC-v1`（SHA-256 `654d59bd4c9ed50b5bc4ce8719ccf283de427f40729526438e3f4e9d2f1bad18`）と照合し、2026-10-16 16:00 UTCに保存されました。公開担当はその原評価と結果/受領記録を確認しましたが、公開要約は原log・実行証跡の代わりではありません。[原本参照と別ホストの限界](omil-current.md#保存範囲と別ホストの限界)を保持します。

次の点検では対象期間・版・母集団を確定し、通常成功だけでなく例外/未完・変更/人介入を含めます。重要な判断が変わる部分を深掘りし、十分な方法は維持します。X6は便益と総負荷を比較して有限に扱う観点、AG4は集中の品質価値と支援負担を判断する観点です。負荷の全項目改善・純利益・最適構成を新しい必須条件へ膨らませません。対象外の機能や未使用DBに評価項目を足さず、未実行を合格にしません。
