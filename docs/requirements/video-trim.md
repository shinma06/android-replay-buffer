# 保存後の切り取りと、シーク位置の静止画（要件）

状態: **要件確定**。2026-11-17 に、全入口を切り取りと PNG 保存ができる編集画面へ統一し、保存して編集した本体を閉じる時の保持・復元可能な退避を定めた（[3.1](#31-編集画面)〜[3.3](#33-保存して編集した本体を閉じる)・AC-13〜AC-23）。切り取り・静止画の精度と CLI / MCP の互換性は維持する。閉じる時だけの保全の変更は CLOSE と SAFE-01 / SAFE-04 に示す。schema 4 の現行コードに基づく。判断は本文書で確定する。確認と統合は[検証方針](../verification/README.md)に従う。

この文書は Trail [#19](https://entire.com/gh/shinma06/-/trails/19)（Issue [#16](https://github.com/shinma06/android-replay-buffer/issues/16)）の要件正本である。2026-11-11 の先行案（`2bfa9b7e`、schema 3 / `session.json` / `video-001.mp4` / 「音声はない」）は現行コードと合わないため、本文書で置き換える。

元の要望（Trail #19）: 保存した動画を IDE 内で開き、前後をカットして保存する。トリミング前と後の2本を保存するオプションを付ける。シークバーで選んだ位置の画面をキャプチャして PNG で保存する。

## 用語

| 用語 | 意味 |
|---|---|
| 保存フォルダ | 「直前N秒を保存」等でできる1回分の完成フォルダ。名前は `replay-<yyyyMMdd-HHmmss>-<manual\|crash>[-logs]-<8桁ID>`（[SaveLayout.kt](../../plugin/src/main/kotlin/io/github/shinma06/replaybuffer/core/SaveLayout.kt)）。使う文字は `[a-z0-9-]` だけ |
| 動画内の時刻 | プレイヤーの再生位置（0 から）。`video-frames.jsonl` の `movie_pts_us`〜`movie_end_us` |
| 記録窓の時刻 | 保存範囲の先頭を 0 とする、動画・ログ・タップ・音声共通の時刻。各行の `t_ns`（schema 4。旧 `window_ns` ではない） |
| 開始点・終了点 | 切り取って残す範囲の始めと終わり（In / Out）。動画内の時刻で指定し、表示中のコマの境界に合わせる |
| 切り取り | 開始点より前と終了点より後を除いた、**新しい**保存フォルダを作ること |
| 静止画（frame） | 保存クリップの、今のシーク位置に表示されている1コマを PNG にしたもの。端末の「今の画面」を撮る既存スクリーンショットとは別 |

## 0. 現行コードで分かっていること（根拠と仮定）

### 保存物（現行）

[plugin-design.md 保存物の構成](../plugin-design.md#保存物の構成)、[SaveLayout.kt](../../plugin/src/main/kotlin/io/github/shinma06/replaybuffer/core/SaveLayout.kt)、[SaveWriter.kt](../../plugin/src/main/kotlin/io/github/shinma06/replaybuffer/core/SaveWriter.kt):

| ファイル | 内容 | 切り取りへの影響 |
|---|---|---|

| `replay.json` | schema 4。`complete`・`save_id`・`folder_name`・`trigger`・`files`・`counts`・`coverage`・`timebase`・`files_sha256` など | 範囲外を落とし、掛かる gap は端で切り詰め、ハッシュは再計算。任意 field `trim` を追加する（schema 番号は 4 のまま） |

作成中は `.<名前>.partial`、完成名へ上書きなしで改名。旧形式（`session.json` / `README.txt` / `video-001.mp4`）は移行も対象にもしない。

### 画面（現行）— シークバーはまだない

保存後の IDE 操作は、ToolWindow と通知の「フォルダを開く」だけである（[ui-ux.md](../design/ui-ux.md)、[ReplayToolWindowFactory.kt](../../plugin/src/main/kotlin/io/github/shinma06/replaybuffer/ui/ReplayToolWindowFactory.kt)、[ReplayProjectService.kt](../../plugin/src/main/kotlin/io/github/shinma06/replaybuffer/ide/ReplayProjectService.kt)）。**保存クリップを IDE 内で再生・シークする UI は存在しない。** 既存の `screenshot` は接続中端末の「今の画面」であり、保存クリップの1コマではない（[ScreenshotSave.kt](../../plugin/src/main/kotlin/io/github/shinma06/replaybuffer/core/ScreenshotSave.kt)、[SHOT-02](../requirements.md#第2版の追加要件スクリーンショット)）。

**仮定（本要件で埋める）:** 「シークバー位置の静止画」を満たすため、保存クリップ用の最小プレイヤー（エディタタブ、シークバー、コマ送り）をこの機能の一部として新設する。プレイヤーが使えない経路（CLI / MCP）では、同じ中核処理を動画内時刻 `--at` / `--from` / `--to` で呼ぶ。

### 同梱部品（現行）

- プラグインは **JCodec** を同梱し、サイズ混在やタップ描画の再エンコードに使っている。
- [project.md](../project.md) により、利用者環境への **ffmpeg / Python / scrcpy の別インストールは前提にしない**。切り取り・復号も JCodec と既存 writer 経路で行う（親依頼の「必要なら ffmpeg 再エンコード」は、同梱 JCodec による再エンコードとして解釈する）。
- CLI / MCP は GUI と同じ処理を共有し、変更時は `docs/cli.md`・`replay --help`・`plugin/src/main/cli/README.txt`・`docs/mcp.md` を同時に更新する（[AGENTS.md](../../AGENTS.md)）。

## 1. 範囲と対象外

### 範囲

- 完成済み（`replay.json` の `complete=true`、`.partial` でない、schema 4、`video.mp4` と `video-frames.jsonl` がある）保存フォルダを対象に、開始点・終了点で切り取った**新しい**保存フォルダを作る。
- 同じプレイヤー（または CLI の時刻指定）で、今の表示コマを PNG にする。
- 中核処理は画面に依存せず、IDE・CLI・MCP が同じ結果を返す。
- ログ・タップ・（あれば）音声・`replay.json` / `README.md` も同じ範囲にそろえる。

### 対象外

| 対象外 | 理由 |
|---|---|
| 保存前バッファ上での範囲指定 | 別機能。本機能は保存済みフォルダだけ。Issue #16 の「保持範囲内の開始・終了位置を指定して保存」「初期版は設定時間分を即保存」は、保存時の範囲指定にも読めるが、Trail #19 と本機能は保存後の切り取りに限定する |
| 複数範囲の切り出し・複数保存の結合 | 時刻対応が複雑になる |
| 拡大縮小・圧縮率変更・GIF/WebM・ぼかし・文字入れ | 別機能 |
| ログ専用（`-logs` / 動画なし）フォルダの時間切り出し | プレイヤーも MP4 もない |
| schema 4 より前、または手編集でハッシュが崩れた保存 | 理由を示して拒否 |
| 外部アップロード | 対象外 |
| プレイヤー上でのログ編集 | 範囲内の件数表示まで |
| 取っ手を止めて押し続けたときの拡大（細かい調整用ズーム） | QuickTime にはあるが今回は入れない。後続候補。今回のフィルムストリップは常に全体表示で、ズーム・スクロールしない |

## 2. 確定した既定と根拠

依頼は判断をこちらに委譲している。旧案の未決事項は次で確定する。

| 項目 | 既定 | 根拠 |
|---|---|---|
| 元の保存 | **常に残す。切り取りは新しいフォルダだけ。CLI / MCP / GUI いずれでも元を消す操作は提供しない**（旧案の「確認付き置き換え」も今は出さない） | Trail #19 の「トリミング前と後の2本を保存するオプション」は、常に両方残すことで満たす。SAVE-04 と AGENTS.md の「データの削除で止まる」。削除は後の Trail に分けられる |
| 切り取り方式 | **先頭 GOP だけ再エンコード（K2）。残りは元 packet をコピー。I-frame へ黙って丸めない** | [timeline.md](../design/timeline.md) は開始点の黙った丸めを禁じる。edit list だけだと切った前の画面がファイルに残る。全体再エンコードは最長 900 秒で重い。JCodec は既に同梱 |
| 出力場所 | 元と**同じ親フォルダ**に新規フォルダ | 元と並ぶ。元の中には書かない（SAFE-01） |
| フォルダ名 | `replay-<yyyyMMdd-HHmmss>-trim-<8桁ID>`（切り取り開始のローカル時刻、文字は `[a-z0-9-]` のみ） | 現行の命名規則に合わせる。UTC や秒の小数点、`T`/`Z` は使わない |
| 静止画の場所 | 既存スクリーンショットと同じ保存先（SHOT-02） | 画像の置き場を増やさない |
| 静止画の名前 | `frame-<yyyyMMdd-HHmmss>-<8桁ID>.png` | 既存 `screenshot-…`（端末の今の画面）と先頭で区別する |
| IDE 再生 | Compose + JCodec でコマ表示・シーク・実時間再生。音声は JCodec に同梱の JAAD で AAC を復号し、JDK 標準の `javax.sound.sampled` で出す（純 Java） | 3 OS で同じ。追加依存なし。JCEF / 外部 ffmpeg / Android プラグイン内部 FFmpeg は使わない |
| CLI / MCP | **初回から同じ中核を公開する**。置き換え（削除）は置かない | AGENTS.md の GUI/CLI/MCP 同一 |

音声: 元に AAC がある場合、切り取り後の `video.mp4` にも同じ範囲の音声を残す。`coverage.audio` / `audio_track` を範囲に合わせて更新する。音声だけ欠ける失敗は保存失敗とし、映像だけ成功として公開しない（mux 不整合を避ける）。`record_audio=false` や元に track が無い保存は、従来どおり音声なし。

## 3. 利用の流れ

1. 「直前N秒を保存」は従来どおり全範囲を保存し、編集画面は自動では開かない。別の「直前N秒を保存して編集」は同じ保存を行い、その要求自身の完成済み動画を編集画面で開く。ツールチップは「保存後に開き、切り取りや好きなコマの画像保存ができます」。失敗・中止・未完成・動画なしでは開かず、ログ専用の取得ではこのボタンを無効にする。
2. 保存完了通知に **「編集」** を追加する。その通知に対応する保存の動画を開き、「フォルダを開く」「動画を開く」「パスをコピー」は維持する。通知からの編集も完成済み動画だけを対象とし、開く時点でも存在と保存形式を検証する。通知・ToolWindow 直近結果の「動画を開く」、`…` の「保存した動画を開く…」（フォルダ選択）、IDE で完成フォルダの `video.mp4` を直接開く経路も、同じ編集画面を使う。
3. エディタタブ「動画の編集」は、どの入口でも全範囲を選んだ状態から始まる（詳細は [3.1](#31-編集画面)）。通常モードとモード切替ボタンは置かない。再生・シーク・コマ送り・切り取り・PNG 保存をここで行い、切り取りをしなくても任意のコマを PNG にできる。最初の正しいプレビューを読み込めば、再生位置や範囲を動かさず PNG を保存できる。全範囲のままでは「トリミング」は無効。
4. 切り取りは明示的に「トリミング」を押したときだけ背景で実行する（進捗と中止は [3.2](#32-キャンセルと中止)）。成功時は元動画の編集画面に残り、範囲を全体へ戻して現在の再生位置を保ち、保存先を開く・動画を開く・編集・パスをコピーの通知を出す。元フォルダは変えない。全範囲のまま何も実行せず閉じても、動画や PNG を書き出さない。
5. CLI 例: `replay trim <保存フォルダ> --from 5.2 --to 12.0`（stdout は新フォルダのパスだけ）。`replay frame <保存フォルダ> --at 7.533`（stdout は PNG のパス）。MCP は `trim_replay` / `export_frame`。時刻は動画内の秒（小数可）。既存コマンドの意味は変えない。


### 3.1 編集画面

参考は macOS の QuickTime Player のトリム（利用者提示の画面写真: 取っ手をつかんでいる状態、再生位置をつかんでいる状態、何もつかんでいない状態）。色や細部までは真似せず、IDE のテーマ（Jewel）に溶け込ませる。

**画面の構成**

| 部分 | 内容 |
|---|---|
| 見出し | エディタタブ上端の1行。保存フォルダ名。開けないときだけ理由を出す |
| 映像 | 残りの高さいっぱい。縦横比を保って収め、余白はテーマのパネル背景色 |
| コントロールバー | 映像の下端に重ねる角丸（10dp）の半透明バー。左右と下に 12dp の余白。背景はテーマのパネル背景色を 9 割の不透明度で、枠はテーマの通常の枠線色 |
| 再生ボタン | バーの左端。再生 ▶ / 一時停止 ❚❚ のアイコン（スクリーンリーダー名は「再生」「一時停止」） |
| フィルムストリップ | バーの中央。**1本だけ**で、**常に動画全体（0〜終了）を同じ縮尺で**並べる。ズームもスクロールもしない。サムネイルは高さ 48dp、幅は動画の縦横比どおり。並べる数は帯の幅で決まり、各枠の中央時刻を含む表示コマを使う |
| 重ね描き | 欠落区間は薄い斜線（サムネイルを出さない）、時刻不明（`timebase.known=false`）は帯の下端に点線、タップ位置は帯の下端に短い目盛り。どれも薄く、主役のサムネイルと枠を邪魔しない |
| トリム枠 | どの入口でも全範囲から始まり、帯の上に**常に**表示する（何もつかんでいないときも）。色はテーマのアクセント色（フォーカス枠の色。QuickTime の黄色は使わない）。上下 3dp の太枠と、左右に幅 12dp の取っ手（中に縦の2本線）。枠の外のサムネイルも見えたまま、パネル背景色で少しだけ暗く（または明るいテーマでは淡く）覆う |
| 再生位置 | 帯の上の 2dp の縦線（テーマの文字色、反対色の細い縁取り）。開いた直後から常に出す。PNG 保存の可否は、その位置の正しいプレビューを表示できているかで決める（下の「PNG 保存の有効化」） |
| 時刻の吹き出し | **取っ手か再生位置を押さえている（ドラッグ中の）間だけ**、押さえている要素の真上に出す。書式 `m:ss.cc`（例 `6:09.22`、100分の1秒は切り捨て）。何もつかんでいないときは、時刻の文字はどこにも出さない（現在位置・残す秒数の常設表示も置かない）。時刻はスクリーンリーダー向けの説明にだけ載せる |
| ボタン列 | バーの右端（配置は下表） |
| 状態の1行 | ボタンが無効な理由、保存結果、音声が出せないなどの知らせがあるときだけ、バーの最下段に1行。普段は出さない |

**ボタン**

| モード | ボタン（上から / 右寄せで左から） |
|---|---|
| 編集画面 | `トリミング`（主ボタン）、`この位置をPNG保存`、`キャンセル`（実行中は `中止`） |

| エディタ幅 | 配置 |
|---|---|
| 640dp 以上 | ボタン列はフィルムストリップの右に縦に積む（主ボタンが一番上。QuickTime と同じ） |
| 640dp 未満 | フィルムストリップを広く取り、ボタンはその下の1行に右寄せで横に並べる。並びは `この位置をPNG保存`・`キャンセル`・主ボタン（主ボタンが右端。IntelliJ のダイアログと同じ） |

ボタン名の文言は途中で改行しない（縦積みでもボタン幅は文言に合わせる）。

**操作**

| 操作 | 動き |
|---|---|
| `I` / `O` | 今の再生位置を開始点 / 終了点にする。モード切替は不要で、PNG 保存の前提操作でもない |
| 取っ手をドラッグ | 開始点（左）・終了点（右）を動かす。指の位置の時刻に最も近い**表示コマの境界**へ吸着する（開始点は表示開始、終了点は表示終了。TRIM-M01。I-frame へは丸めない）。欠落区間の中には置かれない。開始点と終了点は交差せず、最低1コマは残る。ドラッグ中、映像はその端のコマ（開始点ならその最初のコマ、終了点なら最後のコマ）を出し、吹き出しは取っ手について動く |
| 再生位置をドラッグ・帯をクリック | 再生位置を動かす（スクラブ）。表示コマの開始へ吸着し、映像と吹き出しがついてくる。枠の中だけを動く |
| 取っ手を離す | 吹き出しが消える。再生位置が枠の外になったら枠の端のコマへ寄せる |
| `←` / `→` | 1コマ戻る / 進む（枠の中だけ） |
| `Space` | 再生 / 一時停止 |
| `Esc` | ドラッグ中ならそのドラッグだけを取り消す。それ以外は `キャンセル` / `中止` ボタンと同じ（[3.2](#32-キャンセルと中止)） |
| `トリミング` | 枠の範囲で切り取りを背景で始める。中核は TRIM-T / TRIM-M / SAFE のまま。成功したら元動画の編集画面で全範囲へ戻し、再生位置は維持して保存完了通知を出す |
| `この位置をPNG保存` | 押した時点の再生位置の表示コマを PNG にする（FRAME-01〜06）。再生中なら一時停止してそのコマを保存する。範囲はそのまま。初回プレビューの読込後から押せる（PNG-01〜07） |

ドラッグ中の時刻の判定は帯の座標だけで決まる（帯の幅と動画の長さの比。ズーム・スクロールがないので、同じ位置は常に同じ時刻）。

**PNG 保存の有効化（範囲編集の有無に依存しない）**

| ID | 場面 | 再生位置の線 | `この位置をPNG保存` |
|---|---|---|---|
| PNG-01 | 編集画面を開いた直後（全範囲） | 最初の再生位置に出す | その位置の正しいプレビュー読込後から有効・青（アクセント色）。読み込み中・プレビュー準備中は無効。範囲や再生位置を動かす必要はない |
| PNG-02 | 帯のクリック・再生位置のドラッグ・`←` / `→`・再生 | 現在位置に出す（吹き出しは押さえている間だけ） | 現在の表示コマとプレビューが一致するとき有効・青。不一致・準備中・欠落では無効。主ボタンは `トリミング` のまま（並び順・状態の1行の優先は変えない） |
| PNG-03 | 取っ手のドラッグで再生位置が枠の中へ寄せられた | 寄せた位置に出す | 寄せた先の正しいプレビューを読み込めば有効。追加の再生位置操作は不要 |
| PNG-04 | 再生位置のドラッグ中に `Esc` | つかむ前の位置へ戻す | 復元先の正しいプレビューがあれば有効。取消前の別のコマを保存できてはならない |
| PNG-05 | トリミング・PNG 保存の実行中 | 変えない | 無効・中立（理由「保存中です」）。中止・失敗後は範囲と現在位置を維持し、正しいプレビューがあれば再度有効 |
| PNG-06 | 待機中の `キャンセル`、またはトリミング成功 | 現在位置を維持 | 範囲だけ全体へ戻す。現在の正しいプレビューがあれば有効・青。PNG 完了では範囲も現在位置も変えない |
| PNG-07 | 別の動画または閉じた動画を新しく開いた | 全範囲の最初の再生位置に出す（PNG-01 と同じ） | 新しい動画自身の正しい初回プレビュー読込後から有効。前の動画の画像や未完了の復号結果を使わない |

PNG 保存は表示コマとプレビューの一致を検証する。読み込み待ち・シーク直後・復号失敗・欠落では、前のコマの画像が残っていても保存を許可しない。

**無効のときの理由（状態の1行）**

保存結果などの知らせがないとき、主ボタンが無効ならその理由を、主ボタンが使えて `この位置をPNG保存` だけが無効ならその理由を、状態の1行に出す。

| ボタン | 無効になる場面と理由の文言 |
|---|---|
| `トリミング` | 枠が動画全体のまま「範囲が動画全体のままです」／保存中「保存中です」／読み込み中「読み込み中です」／開けない保存「この保存は切り取れません: <理由>」 |
| `この位置をPNG保存` | 再生位置が欠落区間「この位置に表示frameがありません（欠落）」／保存中「保存中です」／読み込み中「読み込み中です」／現在の正しいプレビューがない「この位置の映像を準備しています」（主ボタンも無効なら、状態の1行には主ボタンの理由を先に出す） |
| `キャンセル` / `中止` | 待機中に全範囲なら無効（「範囲が動画全体のままです」）。読み込み中・開けない保存・ドラッグ中も無効。実行中は範囲に関係なく `中止` を有効にし、中止要求後は終わるまで無効（「中止しています…」） |

**再生**

- 映像は専用の1スレッドで、再生開始位置を含む GOP の先頭から順に復号し続ける（コマごとに GOP 先頭から復号し直さない）。表示は時計に合わせ、遅れたコマは表示だけ飛ばす（参照のため復号は飛ばせない）。
- 元に AAC 音声があれば、JCodec に同梱の JAAD で復号し、JDK 標準の `javax.sound.sampled`（`SourceDataLine`）で出す。時計の正は音声の再生位置。音声の欠落区間は無音で埋める。追加依存も外部 ffmpeg も使わない（TRIM-M05 と同じ方針）。
- 音声がない保存は単調時計で映像だけを再生する（知らせは出さない）。音声があるのに出力装置がない・復号できないときも映像だけで再生を続け、状態の1行に「音声を出力できないため、音声なしで再生しています。」（復号できないときは「音声を再生できないため、…」）を出す。切り取り結果には影響しない。
- 枠の終了点で止まる。終わりで再生を押すと選択範囲の開始点から再生する（全範囲なら動画先頭）。
- 滑らかさ（解像度ごとの実効 fps）と音ずれは実画面・音声装置での測定が必要で、本箱では 未確認。

**サムネイル**

- 画面の外（EDT の外）の低優先度スレッド1本で作る。時刻順に連続復号で取り出し、縮小して保存フォルダ単位でメモリに持つ（同じ表示コマは作り直さない）。帯の幅が変わって数が変わったときは、持っているものを使い回して足りない分だけ作る。
- できるまではパネル背景色の空き枠を出し、操作は待たせない。

### 3.2 キャンセルと中止

| ID | 場面 | `キャンセル`（または `Esc`）の動き |
|---|---|---|
| CANCEL-01 | 範囲を変更済み・何も実行していない | 開始点・終了点を全範囲に戻し、編集画面に残る。現在の再生位置を保ち、再生中なら現在の再生時計の位置で止める。モードを切り替えず、**ファイルには一切触れない**。プレビュー準備中でもリセットできるが PNG の一致検証は維持する |
| CANCEL-02 | 範囲を変えていない・リセット済み | `キャンセル` は無効。`Esc` も何もしない（書き出し・巻き戻し・再生停止をしない）。ただし実行中の中止は CANCEL-04/05 を優先する |
| CANCEL-03 | 取っ手・再生位置をドラッグ中 | `Esc` はそのドラッグだけを取り消し、つかむ前の値に戻す。編集画面に残る（ドラッグ中はボタンは押せない） |
| CANCEL-04 | トリミング実行中 | ボタンは `中止` になり、主ボタンは「保存中…」で無効。押すと背景タスクに中止を伝え、`中止しています…` で無効になる。中止が効いたら完成フォルダは作らない。作りかけの `.<名前>.partial` は SAFE-03・既存の保存と同じく**削除せず保全**し、そのパスを状態の1行に出す。元フォルダは読むだけで変わらない（SAFE-01）。編集画面と範囲はそのまま残し、すぐやり直せる |
| CANCEL-05 | PNG 保存中 | 同じく `中止`。復号中なら止めて PNG を作らない。書き込みが始まった後は数ミリ秒で終わるため完了を待つ（既存スクショの `.partial` 規則のまま）。編集画面と範囲は残す |
| CANCEL-06 | 中止が間に合わず完成した | 成功として扱い、通常の成功通知を出す（完成物を勝手に消さない） |
| CANCEL-07 | 実行中にタブを閉じた | 処理は IDE の背景タスクとして続き、進捗表示から中止できる。範囲の指定は保存しない |

**範囲のキャンセル・実行中の中止では確認ダイアログを出さない。** 範囲のリセットやタスクの中止は元の保存を変えず、作りかけも保全する。タブを閉じる際の本体の扱いは、次の独立した操作とする。

### 3.3 保存して編集した本体を閉じる

| ID | 要件 |
|---|---|
| CLOSE-01 | 「保存して編集」のその保存要求から初めて開いた、完成した手動保存だけに一時的な由来情報を持たせる。要求 ID・manifest の `save_id` と `trigger=manual`・保存フォルダとファイルの実体を検証する。由来をパスや最新の選択から推測せず、IDE の保存状態にも永続化しない |
| CLOSE-02 | 切り取りの完成出力がなく、正常・待機中の編集タブを明示的に閉じたときだけ「リプレイ本体も残しますか？」と確認する。「残す」が既定。取消・応答不明・確認不能では残す。成功した切り取りが一度でもあれば従来どおり本体を残し、失敗・取消を成功扱いしない。出力の有無が不明なエラーも本体を残す |
| CLOSE-03 | 通常保存・通知やファイルから開いた動画・クラッシュ自動保存・再起動後の復元タブには確認を出さず残す。通常経路が既に開いている対象タブを返した場合も一時的な由来を解除する。project / IDE 終了、plugin unload、エディタの置換・破棄、読込エラー、実行中のタスクでは本体を残す。`dispose()` から確認しない |
| CLOSE-04 | 「残さない（復元可能な場所へ移す）」を選んだ場合は、デコーダと保存元のハンドルが閉じた後、本体の既知の構成ファイルだけを同じ保存先の `replay-recovery-<UUID>` へ移す。永久削除・期限付き削除は行わない。処理は共通の save handles を使い、OS 分岐を作らない |
| CLOSE-05 | PNG は元の設定先・パスに残す。本体内の PNG も移さず、そのフォルダを残す。未知の構成物・リンク・実体や内容の変更を検出したら本体を移さない。未知の内容を再帰削除しない。元フォルダは空の場合だけ整理できる |
| CLOSE-06 | 移動失敗や終了開始では、既に移したファイルを上書きせず戻す。戻せない競合があれば両方を保全し、元の場所と実在する保管場所を伝える。成功を装わない |
| CLOSE-07 | 保管場所には永続的な `recovery.json` と「復元方法.txt」を置く。通知の「元に戻す」または、再起動後も「保存した動画を開く…」で保管フォルダを選び復元できる。両方の入口で同じ確認を一度だけ出し、復元の既定は「キャンセル」とする。元のパスが再利用されていたら上書き・置換せず保管する。PNG が残る元フォルダは実体と一時的な由来印も照合する |
| CLOSE-08 | 残す選択・未操作で閉じる操作から新しい動画や PNG を書き出さない。退避と復元の失敗時もデータは保全し、外部のゴミ箱 API が成功したと仮定しない |

## 4. 機能要件

### 4.1 時刻（TRIM-T）

| ID | 要件 |
|---|---|
| TRIM-T01 | 開始点・終了点は動画内の時刻で指定し、`video-frames.jsonl` で `t_ns` へ換算する。バイト位置や平均 fps では換算しない |
| TRIM-T02 | ログ・タップ・音声サンプルは、元の保存と**同じ採否規則**で選ぶ。端からの距離が `t_uncertainty_ns` 以内の行は残し、範囲外と証明できる行だけ除く。`t_ns=null` の行は除外と断定せず残す |
| TRIM-T03 | 範囲が `clock_alignment_known=false` に掛かるときは、その旨を処理前に示し（CLI は stderr 警告）、ログは多めに残す。不明を既知へ書き換えない |
| TRIM-T04 | 新しいフォルダは通常の保存と同じ形式（schema 4、同じファイル名規則、同じ読み方）。動画内時刻と `t_ns` は新しい開始点を 0 として付け直し、`replay.json` の `trim` に元へ戻す差分を残す |
| TRIM-T05 | 範囲内の gap / `timebase.clock_steps` / 欠落はそのまま残し、範囲外だけ除く。掛かるものは端で切り詰める。端が null のものは null のまま。gap を 0 秒に詰めない |
| TRIM-T06 | タップの `movie_us` と音声 segment の movie 時刻は新しい動画で付け直す。元が null なら null のまま |
| TRIM-T07 | `replay.json` の `trim` に、元の `save_id`・`folder_name`、元の `replay.json` と `video.mp4` の SHA-256、元の動画内時刻での開始/終了、対応する `t_ns`（不明なら null）、方式 `leading_gop_reencode` を書く。`trigger` は元を引き継ぐ（`manual` / `crash`）。フォルダ名の種類部分は常に `trim` |

### 4.2 切り取り精度とメディア（TRIM-M）

| ID | 要件 |
|---|---|
| TRIM-M01 | 開始点は選んだコマの表示開始、終了点は選んだコマの表示終了。コマの途中で切らない。I-frame へ黙って丸めない |
| TRIM-M02 | 方式は先頭 GOP の再エンコード + 以降の元 packet コピー。開始点より前の画像が、一般的なプレイヤーで見えないこと（ファイル内 preroll を残さない）。再エンコード区間の画質は既存のタップ描画/正規化と同程度を目標とし、劣化があっても範囲外の画面が残るより優先する |
| TRIM-M03 | 元に AAC があれば同じ範囲を mux する。track の有無と `coverage.audio` が食い違ってはならない |
| TRIM-M04 | `video-source.h264` は、元にあった場合だけ、新しい範囲に対応する分を残す。元に無い切り取りで新たに作らない（コピー区間だけなら不要） |
| TRIM-M05 | 外部 ffmpeg バイナリに依存しない |

### 4.3 保全（SAFE）

| ID | 要件 |
|---|---|
| SAFE-01 | 読込・切り取り・PNG 書出しは元フォルダを読むだけ。明示的な閉じる時の退避・復元だけは CLOSE-01〜08 に従う |
| SAFE-02 | 開始前に元の `files_sha256` と実ファイルを照合し、不一致なら理由を示して止める |
| SAFE-03 | 出力は `.<名前>.partial` に書き、検証後に上書きなしで完成名へ改名する。失敗・中止では完成フォルダを出さない。`.partial` の扱いは既存保存と同じ |
| SAFE-04 | 元フォルダの永久削除・置換は行わない。保存して編集の由来がある場合だけ、CLOSE の明示確認後に復元可能な本体退避を認める |
| SAFE-05 | 開ける・切れるのは完成済み schema 4 の、動画付き保存だけ |
| SAFE-06 | 切り取り中も取得は止めない |
| SAFE-07 | ファイル I/O は既存の `HostPlatform.saveHandles`（`PosixSaveHandles` / `WindowsSaveHandles`）だけを通す。呼び出し側で OS 分岐しない |

### 4.4 静止画（FRAME）

| ID | 要件 |
|---|---|
| FRAME-01 | 今表示中（または `--at` が属する）の**表示コマ**を、元の画素サイズで PNG にする。プレイヤーの表示倍率や HiDPI キャプチャは使わない |
| FRAME-02 | 保存先は SHOT-02 のスクリーンショット先。既存ファイルを上書きしない。作成中は既存スクショと同じ `.partial` 規則 |
| FRAME-03 | 時刻の正確さは `video-frames.jsonl` のそのコマの `movie_pts_us`〜`movie_end_us` に属する位置であること。PNG の tEXt（または同等の付属メタデータ）に元 `folder_name` / `save_id`、動画内時刻、`t_ns`（不明なら書かない）を入れる |
| FRAME-04 | 端末の `show_touches` や `tap_display=VIDEO` で動画に焼き込まれた点は、そのコマに写っていれば残る。後から点を足したり消したりしない |
| FRAME-05 | 通知は既存スクショに近い「保存場所を開く」。削除を出す場合は既存スクショと同じ隔離削除だけを使い、元の保存フォルダは触らない |
| FRAME-06 | 色一致の証明にはしない（既存の再エンコード注記と同じ） |

### 4.5 容量・エラー

| ID | 要件 |
|---|---|
| ERR-01 | 開始前に出力サイズを見積もり、既存の空き容量下限を保てなければ始めない。書込み中も既存の `checkSpace` 相当を続ける |
| ERR-02 | ファイル全体をメモリに載せない |
| ERR-03 | IDE では背景タスクで進捗と中止を出す。画面を固めない |
| ERR-04 | 拒否・失敗の例（日本語の理由、推測を事実にしない）: 未完成 / schema 不一致 / ハッシュ不一致 / 動画なし / 範囲が空または開始≥終了 / 範囲が動画の表示区間外 / 書き込み不可 / 容量不足 / 中止。CLI の失敗は 0 以外の終了コードと stderr。stdout には成功パスだけ |
| ERR-05 | 保存先に書けないときは、IDE では「別の場所に保存…」を案内できる。別の場所でも元は変えない |

## 5. 受入条件（検証可能な項目）

テスト合格と IDE / 端末での受入は別に記録する。

| ID | 条件 |
|---|---|
| AC-01 | 合成 fixture で、①切れ目なし、②複数 parts / gap、③ `video-source.h264` あり、④タップあり、⑤ AAC あり、の各保存を切り取り、新しいフォルダが schema 4 として読める |
| AC-02 | 切り取った動画の最初と最後の表示コマが、指定したコマと `video-frames.jsonl` で一致する。I-frame 丸めがない |
| AC-03 | 開始点より前の画像が、出力 MP4 の通常再生で見えない |
| AC-04 | ログ・タップ・音声の採否が TRIM-T02 に従い、`t_ns=null` の行が落ちない |
| AC-05 | 範囲内の gap / clock_steps が残り、範囲外は残らず、null 端は null のまま |
| AC-06 | 元フォルダの全ファイル SHA-256 が切り取りの前後で変わらない |
| AC-07 | 中止・容量不足・例外で完成フォルダが残らない |
| AC-08 | PNG が指定コマ・元解像度で、名前が `frame-` で始まり、スクショ先に上書きせず、メタデータに時刻が残る |
| AC-09 | CLI の `trim` / `frame` の stdout がそれぞれ新フォルダ / PNG のパスだけであり、同じ入力で中核の出力が GUI 呼び出しと同じ（ID・日時を除くバイト一致を単体で確認） |
| AC-10 | 同じ入力・同じ範囲の出力が Linux / macOS / Windows で、名前の ID・日時を除きバイト一致する（`os-parity`） |
| AC-11 | 既存の `start|stop|save|status|screenshot|settings` の意味と終了コードが変わらない |
| AC-12 | 実端末または Emulator で作った保存をプレイヤーで開き、シーク・コマ送り・In/Out・切り取り・PNG ができること — **本箱では KVM 不可のため実装時は 未確認**。単体と CLI で代替し、VM 受入に残す |
| AC-13 | フィルムストリップは1本で、帯の座標と時刻の対応が帯の幅と動画の長さだけで決まる（ズーム・スクロールなし）。トリム枠は何もつかんでいないときも描く（単体: 座標変換とヒット判定の純関数） |
| AC-14 | 取っ手のドラッグ・`I` / `O` で、開始点が表示コマの表示開始、終了点が表示終了に吸着し、欠落区間に置かれず、交差せず、最低1コマ残る（単体: ドラッグの reducer） |
| AC-15 | 時刻の吹き出しは取っ手か再生位置を押さえている間だけ出て、離す・`Esc` で消える。何もつかんでいないときは時刻の表示がない（単体: 表示状態の関数） |
| AC-16 | CANCEL-01〜03 が reducer で成り立つ（全範囲リセットと現在位置の維持、全範囲では no-op、ドラッグ取消）。CANCEL-04 の中止で完成フォルダが残らず元が変わらない（AC-06 / AC-07 と同じ確認） |
| AC-17 | ボタンの文言・有効/無効・理由が 3.1 の表どおり。幅 640dp を境に縦積み / 横1行になる（単体） |
| AC-18 | 再生は連続復号で実時間に進み、AAC があれば音声も出る。出力装置がないときは映像だけで再生し理由を出す（単体: 音声の時刻対応と無音補完、連続復号の結果が `decodeAt` と一致。実画面・実音声は 未確認） |
| AC-19 | ライト / ダークのどちらでも色がテーマから決まる（目視は 未確認。ヘッドレス描画のプレビュー画像で代替） |
| AC-20 | サムネイル作成と復号は EDT の外で行い、帯の幅が変わっても作成済みのものを使い回す（単体: キャッシュ） |

| AC-22 | 保存して編集はその要求自身の完成済み動画だけを開く。通知の編集も対応する保存を開く。動画を開く・フォルダ選択・provider の直接読込を含む全入口が全範囲の編集画面から始まる。通常保存は自動で開かず、未操作で閉じても出力を作らない。失敗・取消・動画なし・無効な保存・破棄後には編集を開始しない（単体） |
