# コンテキストの置き方

| 内容 | 正本・形式 | 読込条件 |
| --- | --- | --- |
| 常時制約と入口 | AGENTS.md、英語 | セッション開始 |
| Claude入口 | CLAUDE.md → AGENTS.md | Claude読込。独立規約を作らない |
| 作業手順 | `.agents/skills/*/SKILL.md`、英語 | 該当作業時。Claude経路はsymlink |
| Cursor入口 | `.cursor/rules/harness.mdc` | projectで常時適用 |
| プロジェクト事実 | project.md、共有docs、日本語 | 判断に必要な範囲 |
| チーム連絡と窓口 | [team-communication.md](team-communication.md)、[窓口依頼文](human-liaison-prompt.md)・[作業担当依頼文](team-worker-prompt.md) | チーム編成・引継ぎ・本人判断時 |
| 独立レビュー依頼 | [review-prompt.md](review-prompt.md)、英語 | 固定HEAD/baseを別sessionへ渡すとき |
| 作業の進行・受入 | Issue/PR | 開始、再開、レビュー、終了 |
| OMILの現行判断・限定結果・点検運用 | [現行入口](omil-current.md)、[フェーズ点検](omil-phase-review.md) | OMIL/PMの開始・引継ぎ、重要変更・中間/終了点検 |
| 証拠 | SHA/版/観察者付きの記録 | 該当Case |
| 個人設定・認証・一時状態 | Git管理外 | 初期化・復旧 |

セッション経緯は当該Issueへ残します。文章だけで内部推論保存や自動compactionを保証しません。ファイルの存在、実読込、実行成功は別です。リンク検査は存在だけ、意味・優先順位・client検出はレビューとsmoke testで確認します。

制約を移す際は適用条件、承認範囲、所有権、完了条件、互換性、原証拠を保ちます。個人の専門領域・モデル固有制限は全利用者へ自動適用せず、必要な導入先だけで設定します。

## 更新時の古い管理前提

方法・tool・方針を更新する担当とレビュアーは、変更した前提の参照先を追い、正本文書、有効plan/resolver/gate、template・担当引継ぎ、実際の利用箇所のうち影響する現行指示を整合させます。履歴と原証拠は保持し、置換済みの手順・制限を現行の義務へ戻しません。元の観察専用割当、固定時間/即時cleanup、特定GUI必須などを引き継ぐ場合も、今の有効条件と適用範囲を確認します。正式契約の変更が必要なら既存の改訂・独立レビュー手順に従い、黙って免除しません。

残す管理上の負債は理由・影響・owner・具体的な解消条件を既存Issue/PRへ記録します。実行中の割当をその場で書き換えず、影響する次操作の前にownerと整合した条件を読み戻します。新台帳/チェックリストを増やさず、無関係な規約の一括改稿、実互換性の削除、履歴削除で負債を消しません。文書の更新・リンク存在・実際の読込/実行と効果は区別します。

旧 `prompts/review.md` は導入時の依頼文を保持する履歴で、新しいレビュー割当には上表の現行依頼文を使います。旧依頼を受け取った場合も、Cursor参照の条件は [現在の方針](android-studio.md)へ読み替えます。元の固定受入・独立性・権限・品質条件は保持します。
