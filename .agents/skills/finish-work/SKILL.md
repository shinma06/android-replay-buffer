# Finish work

Use docs/workflow.md and the Issue acceptance; for context changes also docs/context.md. Review-only requests return findings/evidence without new Issues or writer mutations.

For a method/tool/policy update, follow docs/context.md's superseded-management guidance: trace affected active rules, effective plan/resolver/gates, templates/handoffs and actual consumers; reconcile them while preserving history and explicit contracts. Record retained debt with reason, impact, owner and a concrete retirement condition in the existing Issue/PR, without a new ledger.

Review docs/workflow.md's method-improvement cycle when applicable, including concrete nonfatal friction: a guarantee-preserving alternative, bounded reversible trial and feedback for adoption/refinement/reversion. An improvement chosen for execution needs an actual trial/result/feedback and named owner; proposed/static comparisons alone are not completion. Keep blocked/unperformed trials unfinished with their owner/next action, without invented efficacy, endless experiments or unrelated GUI tests. Do not freeze a method instead of a necessary formal revision.

Run `python3 scripts/check.py` for the harness and relevant real project checks. Do not repeat successful unchanged checks without reason. Include mixed/unknown impact and explicit build/GUI requirements; a skip is not a test pass.

For acceptance-NG corrections to develop, require the preserved original failure record and every failed guarantee to pass on the corrected frozen candidate/artifact under docs/verification/README.md. Separate automatic provenance checks from substantive independent evidence/method assessment. The independent report must bind repair_revision and supply repair_assessment from a canonical originating session distinct from every original writer, repair executor, retained-evidence assessor and compositor; verify complete observation attribution against sealed receipts and bind manual reports in the reviewer's own session with the trusted adapter and the private verified acceptance/original receipt bundle; require the adapter-issued origin_receipt to bind the complete report/current binding through the same private registry, and repair_evidence_sha256 to match the current rehashed bundle, and preserve raw reports only in the private registry with a bound public fingerprint projection; related unit PASS alone cannot erase native NG. Preserve fixed canonical path/hash identities of every retained bundle/mapping/receipt in the existing private registry; check historical existence, ownership, effective file/real-ancestor privacy, content identity and cleanup containment at rebind and all integration/closure/cleanup boundaries. Preflight the effective existing bundle even when replacement is omitted. Unbound legacy history requires explicit adapter-issued original report/binding recovery via --retained-review, never silent resealing or fresh approval. Check the same report before manually publishing Agent review success or merging, and re-read current HEAD/base/Issue/feedback/acceptance and the live trusted main contract immediately beforehand. After merge and during feedback recovery, recompute develop acceptance from the fixed reviewed HEAD/base and current original-NG comment/main, then validate the independent assessment again before handoff and closure/cleanup. A main-push retry or old CI success is not an atomic cross-ref merge guarantee; retain pending on lookup/retry failures. Ordinary unrelated unrun Cases remain tracked, and historical merged PRs are not reclassified.

Read back and validate the current PR title and, for branches created under the adopted naming rule, branch type/purpose/owning Issue consistency under docs/work-management.md before fixed review and merge. Preserve readable existing branch forms without retroactive rename. Read back newly authored commit titles/body under the same adopted commit rule; assess actual per-commit type/Issue/purpose and documented generated merge exceptions without rewriting or retroactively rejecting sealed history. Title changes invalidate the shared review binding even at unchanged HEAD; reconcile live policy and independent assessment. Review meaningful Japanese summary, actual type and any breaking-change rationale; a character check cannot establish prose quality. Preserve the current title in the integrated commit payload and the existing Development/closure guards.

Freeze HEAD/base and obtain separate-session review. Self-review or a script declaring success is not independent approval. Resolve concrete defects before integration. For applicable shared-plugin/harness work, verify the Cursor reuse record required by docs/android-studio.md: fixed source evidence, adoption/adaptation or non-applicability, and checks on this project’s own build. Upstream passes never replace local acceptance. New sessions must satisfy actual user authorization and client execution policy.

Before review/completion, use the read-only `python3 scripts/workflow/agent_loop.py feedback --pr N` snapshot (save raw output privately). Read every review body, inline/reply and PR/Issue conversation through pagination, including bots and resolved/outdated findings. Record each actionable ID/URL, original commit, fixed-current code/tests and disposition in the existing Issue/PR before freezing the feedback snapshot for independent review. Reviewer output uses the private fixed report or coordinator review state; a later public receipt is new feedback to read back, not a reason to post another repeating receipt. Fixed/merged/resolved and a writer's reply alone are not proof. Unknown/unresolved findings block integration.

Marking a draft ready can start asynchronous Codex review. The expected current-HEAD Code Review must have an observable Completed provider summary before completion; absent, pending, failed, stale or unknown-format signals stay pending. Empty comments, CI success, an old review/reaction or elapsed time do not establish completion. Read the terminal review and all findings, then arrange independent review of the resulting fixed revision. Re-fetch the snapshot immediately before merge; any HEAD/base/feedback change invalidates the disposition/review. No fixed sleep, perpetual monitor or extra human approval. If completion cannot be observed within the current work window, hand off the pending run and next readback, not a pass. Provider summary format/short commit identity is a visible service signal, not an independent code approval or proof that no later review will occur.

Read feedback back after merge and before closure. Later arrivals/edits reopen the affected scope in the existing Issue or a concrete fix Issue, link the originating review and keep earlier approval as a historical snapshot. Do not silently preserve an old pass or resume an archived writer. The coordinator uses the same feedback hash/remote pending state and final pre-merge readback; no coordinator enrollment or worker permission is created by this procedure.

On handoff stop the writer and record owner, SHA/base, dirty state, checks, remaining acceptance and next action. Keep paths/hosts/tokens private. Do not overwrite registry or resume PAUSED jobs. Use scripts/workflow/agent_loop.py only from trusted main, for enrolled work with an authorized worker execution route. Follow docs/setup/automation.md; child-process restrictions still apply.

Read current CI, PR merge and Issue acceptance back. Reconcile native PR sidebar metadata under docs/work-management.md, including PR-specific labels/Project Status and actual assignee/Milestone/review requests; preserve related Issue state and distinguish provider reviews from independent assessment. Reconcile Development links and actual default branch/PR target under docs/work-management.md. Before retargeting to default main, remove manual closing links for unfinished Issues and check body/commit closing keywords. For deferred main links, complete post-merge feedback/acceptance/handoff, manually close the completed Issue, then link the merged PR and read both ends plus the unchanged close state/time and matching Issue/status labels/Project Status; have the owner correct and read back drift. Missing or unsupported links stay pending with owner/next action; automatic closure is not scope completion. Close only completed scope; transfer pending verification with bidirectional links, steps, expectations and owner. Merge does not prove release, GUI pass or cleanup. Apply docs/workflow.md’s branch lifecycle to merged and closed-unmerged/withdrawn/superseded PRs separately. Closed, age, names, gone or ancestry alone never prove disposal or release claims. Confirm stopped ownership/PM custody, PR/replacement, exact refs/worktree state, unique work and needed artifacts under that contract. Before retiring unmerged work, use existing recoverable archive/snapshot/bundle outside removal scope, hash/read back and actually restore fixed content; retain QA/recovery/resumption resources with owner and conditions. Never enroll closed-unmerged work into merged-only automation. Re-read live identities before removing only explicitly owned, stopped, clean resources, then verify each result. Never delete main/master/develop. Record retained resources and resumption conditions.

For team work, use docs/team-communication.md and the supplied PM/liaison routes. Keep technical results in concise agent packets; route genuine human decisions through PM to the liaison using native choice cards. Do not turn routine work or handoffs into new human approval gates. Preserve higher-priority output and actual tool permission requirements.

For verification assignments and evidence assessments, review the guarantee → existing evidence → missing fact → method basis in docs/team-worker-prompt.md against the actual cited records and docs/verification/responsibility.md. Name any uncovered effective guarantee and why it needs the proposed layer/action; reject unsupported repeats or prerequisites instead of validating the inherited procedure. No missing fact means no new execution. A source/artifact/gate-readiness verdict is limited to that scope and does not approve a future method's sufficiency or acceptance. Preserve explicit effective contracts, immutable originals/failures, artifact/condition binding, full data/content/timing, pin/atomicity/ownership and actual integration; related unit PASS alone cannot erase native NG. Separate safety stops from evidence success conditions. Unknown/changed conditions or unresolved owned failures stay unmet; method revision is not execution or relabeled PASS. Keep this assessment in the existing assignment/report without a new ledger or approval gate.

For any remaining UI/OS/consumer fact, check qualified existing observations, production regression/FILE and installed API/IPC/CLI plus actual image/render readback before extra GUI. Command success is not rendered correctness. Do not rebuild/retest unchanged artifacts merely for an explicitly reviewed method revision; reassessment requires exact provenance, conditions and complete effective coverage.

Where existing tools lack capability, review consideration of a minimal verification harness/tool with official capability/version/compatibility and setup/maintenance cost versus recurring GUI cost. Prefer Homebrew and distinguish test-host tools from product dependencies. Do not demand a speculative install for this review or add an approval gate to already authorized scoped installs; retain actual tool/OS consent and safeguards.

Review player and editor evidence separately: verify the owned defect requiring each added consumer action, qualified existing observations and unchanged relevant artifact/format/route/runtime/display conditions. New video conditions or text values alone do not justify repeated editor searches; keep full FILE coverage and actual notification/open/copy/error glue. Unknown or changed conditions remain unmet until the affected proof is obtained; this clarification is not a Case result or a relaxed reuse gate.

For product repairs, apply the guarantee-level impact certificate in docs/verification/README.md when reusing unaffected successful facts across changed ZIPs. Keep immutable originals and both identities, current load/integration facts, all effective contracts/deferrals and original-NG repair gates. Require substantive independent provenance/impact/coverage review and a trusted-main Issue certificate; unknown impact or affected guarantees need fresh facts. A policy-only update does not require rebuilding the product. Do not restore strict whole-artifact or prior-promotion requirements from the older reuse path to this separate assessed-fact path.
